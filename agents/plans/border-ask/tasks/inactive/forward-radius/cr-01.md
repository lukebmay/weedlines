## Summary

`lengths['corner_radius']` is the stored user-unit radius.
When the key is set, `_ask_border`, `_ask_surrounds`, and
`_solver_request` put it on the request. The child passes
it to `piece_border`, `build_surrounds`, and
`generate_weeds`. When the key is absent, those calls omit
it and the borders stay square. Zero is passed through.
A missing key is not zero. A change of the stored value
makes the border and the surround stale.

The parent only builds the request. `_begin_ask` was not
edited and still spawns the worker. The library calls stay
in the child functions. The ask does not read a scale and
does not build the rectangles.

## Checks

- `python3 -m pytest tests/test_border_ask.py`: 2 passed in 0.07s. PyQt6 6.7.1. No Inkscape. The test does not open a window.
- With `lengths['corner_radius']` set to 4, all three requests carry 4, and the three library calls receive 4. The border paths have curves.
- With the key absent, the requests omit it, the calls omit it, and the border paths are move and line only.
- Zero is sent and received as 0. The border paths stay square. After a square ask, setting the key makes the border and the surround stale.
- `form.py`, `tests/test_window_border.py`, and the library have no diff. `tests/README.md` adds one sentence for `tests/test_border_ask.py`.
- The thread check has no test of its own. The new test calls the child functions in-process. The product path still goes through `_begin_ask`, which still uses the spawn worker.

## Form

Confirmed.
`extensions/inkscape/weedlines_dialog/form.py`
`_on_piece_length` returns when the key is not `None`,
`inner`, or `border`. `change_piece_length` is that
method. `change_piece_length('corner_radius')` returns
before an ask. `form.py` does not store the key.

That is already
`agents/plans/piece-border/tasks/active/border-options/task.md`.
That task owns `form.py` and `tests/test_window_border.py`.
It says the radius calls `change_piece_length`, a change
of the radius asks for the border, and the value stays
while the window is open, including while the box is off.
It is allowed to close this. It must not edit the ask.

"Store the radius on `lengths['corner_radius']` only
while rounded corners are on" would drop the kept number
if that key is the only copy. The preview keeps the
number while the window is open. The radius applies only
while the box is on. This ask forwards the key whenever
it is set, so the key is what applies the radius. Keeping
the number and applying it are not the same.
