# cr-01

Two defects remain. The named checks passed. Restart during a
border ask drops a showing surround. A solver queued during
that ask keeps the subject and the lengths from the click.

## Defects

1. Restart during a border ask clears a showing surround and
   does not ask again. In `on_start`
   (`extensions/inkscape/weedlines_dialog/run_controls.py`)
   a surround Start sets `surround_finished` false, clears
   `surround_paths`, and returns when `_ask_surrounds` cannot
   start because the ask is still `border`. It leaves
   `surround_inflight` as the finished tuple. `_follow_surround`
   (`extensions/inkscape/weedlines_dialog/geometry_ask.py`)
   asks only when that tuple is stale or is `None`. A Restart
   that did not change distance, join, swap, or inner distance
   matches, so the surround stays gone and the button stays
   Restart. A first Start still works, because `surround_inflight`
   is already `None`. Observed: surround showing, border-width
   change held in the child, Restart clicked while `ask` was
   `border` and the child was alive. After the reply,
   `surround_args` was still 1 and the calls ended
   `piece_border`, `surrounds`, `piece_border`. Remedy: when
   the surround ask cannot start because a border ask is in
   flight, clear `surround_inflight` before returning.
   `_follow_surround` already treats that as waiting. Add a
   test that holds the border ask, clicks Restart, and requires
   the surround to be asked again and stroked.

2. A solver Start queued during a border ask keeps the path
   and the lengths from the click. `on_start` packs
   `solver_request` and returns. `_follow_surround` starts that
   object unchanged. Swap, mode, and `change_piece_length` stay
   enabled, and the padding, spacing, and collar spins stay
   enabled. The hook stores a length before it is called, so a
   later return from the hook does not undo the store.
   Observed: frame Start during a held opening border, then
   Swap. The calls were `subject`, `piece_border`, `subject`,
   `piece_border`, `solver`, and `worker_swaps` ended `True`.
   The keep was 14 by 20, the unswapped letter, not the swapped
   subject. A second run stored inner 13 and border 13 before
   the follow. The border reply was `(13, 13)`. The solver
   received `(12, 12)`. Remedy: build the request when the
   follow starts it, from the current subject, padding, spacing,
   collar, inner distance, and border width. Keep the mode from
   the click. If the current mode is no longer that mode, drop
   the request and clear that mode's `cut_started` instead of
   running it. Add a test for the swap and for the stored
   lengths.

## Summary

The window stores an inner distance and a border width with
the other user-unit lengths. Each default is one eighth of an
inch under `user_unit_scale`: 12 with no scale, 3.175 at one
millimeter. Neither path sends 6.35. The same spawn asks for
the border when the figure check is clear, including on open,
without Start. The child calls `piece_border`. This thread
unpacks the paths and strokes them in the weed-line color. It
does not build them. A defect does not ask and does not paint.
A color change repaints and does not ask again. A held ask
still lets a timer run, and the rectangles wait for the reply.
The first subject paint and the ready callback stay on the
subject turn. The border ask is the next turn. One ask at a
time. A reply whose subject or length is already stale is not
painted. Swap asks again after the new subject is stored.
Either stored length asks for the border again. When a
surround is showing, the inner distance also asks for the
surround. The border width does not. The surround ask passes
`inner_distance`. The form has no new length option and no
invented label. Island-hop stays a mode. The library was not
edited.

The deferred Start is the hole. The follow does start a first
surround, and it does start a queued solver, but only with
the state captured too early.
