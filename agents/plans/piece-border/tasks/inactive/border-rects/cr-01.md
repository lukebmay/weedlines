## Summary

`piece_border(subject, inner_distance, border_width)` in
`src/weedlib/piece_border.py` returns two `QPainterPath`
rectangles, inner then outer. The inner one is the
subject's `boundingRect()` expanded by `inner_distance`
on every side. The outer one is that rectangle expanded
by `border_width`. The lengths are user units, used as
given. An empty subject returns `()`. The name is
exported from `weedlib`.

## Checks

- `QT_QPA_PLATFORM=offscreen python3 -m pytest tests/test_piece_border.py`: 8 passed in 0.05s. No Inkscape. The test file does not import `inkex`. It skips on `ImportError` when Qt cannot load, the same gate as `tests/test_surround.py`.
- A subject at (4, 5), size 10 by 20, with lengths 2 and 3, returns an inner rectangle at (2, 3), size 14 by 24, and an outer rectangle at (-1, 0), size 20 by 30. Those lengths are not converted from inches.
- A diagonal stays an axis-aligned box. A vertical line still returns both rectangles. A lone move is empty and returns `()`.
- A path that is not the argument does not grow the bounds. A hole inside the subject does not shrink them. A cubic uses the drawn bounds (inner height 24.5), not the control-point box (32).
- Each returned path is a closed axis-aligned rectangle: four corners, moves and lines only, and each side shares an x or a y.
- `weedlib.piece_border` is that function, and the name is in `weedlib.__all__`. The `__init__.py` diff is the import and that name.
- `src/weedlib/surround/` and `src/weedlib/solvers/` have no change. `src/weedlib/figures/` has no change. The function does not call `generate_weeds` and does not clip a surround.
- `tests/README.md` has one sentence for `test_piece_border.py`.

## Fit

The piece is the subject. The piece size is that
subject's axis-aligned bounds, not the page and not a
figure outside the subject. The function does not read a
scale. The one-eighth-inch starts stay with the caller.
Units stay document user units, as the boundary part
describes.
