## Summary

The change fits the task. Each of the four settings is a tinted
button in `form.py`. The object names are unchanged. Clicking
one opens a non-native Qt color dialog. Accepting commits
through `_commit_color` and the option history a finished color
edit already used. The button text and its fill become that
color. The other three stay as they were. The initial colors
are still `#E6E6E6`, `#CFCFCF`, `#FF0000`, and `#FFFFFF`.

Cancelling, or undoing text still being typed in the picker's
hex field, does not enter the history and does not change the
preview. The next undo then takes the previous committed
option. Custom colors are hidden so the dialog does not write
a Qt preferences file. The arrow colors stay `#FF00FF`,
`#FF6A00`, and `#00E5FF` in the library. The form has no
picker setting for them.

A solver run still disables the four buttons, so the picker
does not open. A border ask is not a run. It still allows a
color, as it did before. Apply still returns the weed-line
color. `preview.py`, `run_controls.py`, the dialog README, and
the guide were not edited.
