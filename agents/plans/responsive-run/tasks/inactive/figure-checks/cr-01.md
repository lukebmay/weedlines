## Defect

`_one_point_per_region` calls `_crossing_regions`, which reaches `_linked_mark_groups` and does check once per mark. After that call returns, three loops run with no `progress.check`:

- each polygon point against later polygon points, through `_segment_in_both`
- each polygon point against each region, through `_meets_region`
- each region against later regions, through `_sample_sets_meet`

The check at the start of `_overlap_defects` is already over by then. The last mark check is also over. Nothing in these loops checks, so Pause and Clear All wait until the merge finishes.

Three ellipse pairs are enough. Each figure is three `addEllipse(2.5, 2.5)` copies, centers 3 apart, and the other figure is the same set shifted by 1.2. The copies in one figure do not overlap each other. Each ellipse overlaps its shifted partner. `classify_figures` takes about 1.46s and the longest stretch with no check is about 1.06s, all of it after `_crossing_regions` returns. Four pairs take about 3.51s, and that stretch is about 2.79s. Six pairs leave about 10.6s after the last mark check. The same merge on the 96-side thin ring the tests already run is about 0.49s, in the polygon-point loop, which is why a gap measured only between checks stays under a tenth of a second on that ring.

The named tests never enter this merge. Two squares do not build separate regions. The mark-walk test returns inside `_linked_mark_groups`, before these loops.

## Remedy

In `_one_point_per_region` only, call `progress.check()` with no outline and no line:

- once per polygon point, at the start of the outer point loop, before that point is compared with later points
- once per point against one region, before `_meets_region`
- once per region pair, before `_sample_sets_meet`

Two figures are in the merge, so do not name either outline, and do not name a line. Do not add the check inside `_segment_in_both` or `_piece_hits`. Those run from the mark walk as well, and a check on every probe is the long work. Do not change the points the function returns. Do not catch `WeedCancelled`. Do not edit `progress.py`, the solvers, the surround, or the window.

Add a test the current code fails. Use a figure with at least two region comparisons after the mark walk. The two-subpath circles already in `tests/test_figures.py` do this: one outer circle and two ellipses. A focus hook must see a check while a later region comparison is still waiting, not only a check before the merge starts. A cancel that becomes true only after `_crossing_regions` returns must raise `WeedCancelled`, and `classify_figures` must not return a result. No Inkscape. The assertion is the check, not the wall time.

## What held

`_without_twins` checks once per subpath and names that subpath. On 200 separate squares the longest of those gaps was about 8ms. `_self_overlap_defects` checks once per border piece and names that piece's subpath. An 800-segment zigzag took about 0.54s, and the longest gap was about 1.2ms. `_overlap_defects` checks once per pair and names neither figure. `_linked_mark_groups` checks once per mark and names that one border. On the 96-side ring the longest gap inside the mark walk was about 14ms. An 8 by 8 of overlapping squares took about 0.55s, longest gap about 1.4ms. Two offset 64-gons took about 0.45s, longest gap about 18ms.

No call passed a line. A geometry hook counted no cuts, so a name is not a cut. Each named outline was one flat sequence of `(x, y)` points. The ring's longest name was 97 points, one 96-gon, not both borders. An ellipse's name was its five endpoints, one subpath. No check named both figures. `WeedCancelled` is not caught, so a cancel at a check does not return a partial `FigureCheck`. With no hooks, the six-pair defects matched the run that had a focus hook, and the existing figure tests still match.

A cubic is named by its endpoints, not by samples along the curve. That is one outline, not a line, and not a second defect.
