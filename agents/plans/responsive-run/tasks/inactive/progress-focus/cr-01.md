# cr-01

No defects remain. The named checks passed.

## Summary

The change fits the task. `progress.check` names one object
outline and one candidate line, then pauses and cancels through
the existing `check_cancel`. `report`, `check_pause`,
`check_cancel`, and `report_segment` are unchanged.
`check_cancel` does not name and does not clear a name.

The host installs `focus(outline, line)` on `progress.install`.
Each argument is a tuple of `(x, y)` points, or `None` when that
mark is absent. A line is exactly two points. Callers may pass
it as `(x0, y0, x1, y1)` or as two points. An omitted name or an
empty sequence is no mark of that kind. A call that names
neither sends `(None, None)` and clears the previous name. The
host receives a copy. A `QPainterPath` is rejected. The geometry
hook is not called, so the name is not a cut.

With no hooks installed, `check` still returns. Pause blocks
inside `check` until the host clears it. Cancel during that
pause raises `WeedCancelled`.

## Checks

- A host that installed no hooks can still call the check.
  Covered by `test_check_with_no_hooks`. `check()` returns, and
  so does a call that passes an outline and a line.
- Pause blocks in the check and then returns when the host
  clears it. Covered by
  `test_pause_blocks_in_check_then_returns`. The worker stays
  in `check` while the pause hook is set, then the thread ends
  after the hook clears.
- Cancel during that pause raises `WeedCancelled`. Covered by
  `test_cancel_during_check_pause`.
- A named outline and a named line reach the host, and a check
  that names neither clears the previous name. Covered by
  `test_check_names_reach_host_and_clear`. The host gets a
  tuple copy: appending to the caller's list does not change
  it. A flat line `(0, 1, 3, 4)` arrives as two points, and
  two points arrive as two points. Naming only an outline
  sends `None` for the line, and naming only a line sends
  `None` for the outline. `check()` and an empty outline and
  line send `(None, None)`. `object()` raises `TypeError`
  and does not call the host. `report_segment` still delivers
  `(x0, y0, x1, y1)` and does not change the name. The
  geometry hook is not called for the name.
- `pytest tests/test_progress.py` passed: 8 passed. The run
  did not start Inkscape.

## Note

The test rejects `object()`, not a constructed `QPainterPath`.
The same gate rejects a `QPainterPath`, a `QPolygonF`, and a
`QPointF` with `TypeError`. The host receives plain tuples
either way. That is the requirement, so the missing
`QPainterPath` assertion is not a defect.

Importing `weedlib` still loads the solvers and a Qt binding,
so this file does not collect when no binding loads. The new
tests do not construct Qt objects. The older solver tests
still load Qt. Solvers, the surround, the figure check, and
the window were not edited.
