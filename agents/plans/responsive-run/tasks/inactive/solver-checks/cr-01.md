## What held

The change fits the task and the runtime part. `progress.check` runs inside the stretches that used to finish with no check until a segment was accepted. `progress.py` was not extended. `report`, `check_pause`, `check_cancel`, `report_segment`, the `_add_seg` check, and the island-hop phase names are unchanged. The weed path is unchanged.

`frame_weeds` calls `progress.check()` before the rectangle is accepted. `_grid_in_region` names each vertical and horizontal trial line before that line is clipped. `_seg_body_clearance_ok`, `_is_parallel_hug`, and `_require_connected_ends` each check once per trial segment. `_mouth_seal` names only the trial line, on each pair. `_body_pocket_seals` names that one body and its mouth, and `_iter_bay_far_ends` names each coast trial.

A name goes through `progress.check`. That copies the coordinates and does not call the geometry hook, so the name is not a cut. The outline is the first ring of that one body. The line is one segment. With no hooks, `check` returns and does not change the path. `WeedCancelled` is not caught on these paths, so a cancel raises before the function returns a path.

A check on every edge comparison is not required. One check per trial already lands inside the long passes, and each of those gaps is well under a second.

## Checks

- Frame, grid, and island-hop still return the same weed paths. Covered by the existing locks in `tests/test_weeds.py`. A grid and a U-shaped keep were also compared with a focus hook installed and with no hooks. The segments matched.
- On a keep large enough that grid emits many lines, a cancel hook set at the start raises `WeedCancelled` before the function returns the finished path. Covered by `test_large_grid_cancel_at_start_raises`.
- A host records a check from frame and from grid before the first accepted segment. Covered by `test_frame_and_grid_check_before_first_segment`. Grid's checks before that segment each name one line.
- A seal search records line checks while emits are still going, and cancel from that search raises with no path. Covered by `test_seal_search_checks_while_it_runs` and `test_cancel_during_seal_search_returns_no_path`. The seal checks name a line and no outline.
- A U-shaped keep records a pocket check that names one outline and one mouth. Covered by `test_pocket_search_checks_while_it_runs`.
- With no hooks, `check` returns. Covered by `test_check_with_no_hooks`. The path tests still match.
- `pytest tests/test_weeds.py tests/test_progress.py` passed: 151 passed, 4 skipped, 125.16s. The run did not start Inkscape.

## Outside this change

Grid hatch lines are not sent to the geometry hook until `grid_weeds` calls `_publish_path_segments` after the connected-ends pass. A work-rect side that is not already a hatch line is sent once from `_add_path_segs` and again from that publish. File `src/weedlib/solvers.py`. On an 80 by 60 keep, padding 2, spacing 20, the hook receives 20 segments and the path has 18. These two sides are each delivered twice: `(82, -2, 82, 62)` and `(82, 62, -2, 62)`. This change did not touch those calls. The diff only inserts `progress.check`, and that hook does not call the geometry callback. Already true before this change. Not a remedy for this unit.
