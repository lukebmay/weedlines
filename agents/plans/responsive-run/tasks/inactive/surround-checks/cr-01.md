# cr-01

## Result

One defect remains. `pytest tests/test_surround.py tests/test_progress.py` passed (34 passed, 4.29s). Qt loaded. The run did not start Inkscape.

Pause and cancel still cannot take effect during three edge loops. On a fine outline that wait is almost the whole `build_surrounds` call. The outlines, the names, and the progress API are otherwise as the task asked.

## Defect

`_straighten_colinear` walks every straight side against later sides and does not call `progress.check`. `_finish_outline` runs that walk before its own check. A 400 by 220 ellipse at distance 8 dilates to one ring of 2016 points and 252 straight sides. The side walk takes about 2.5s. `build_surrounds` on that ellipse takes about 2.0s and records 7 checks, all outside that walk. Clear All during the walk does not raise until the function is about to return.

`_gap_overlap` has the same hole. Two rings of 2016 points take about 2.6s in the edge-pair loop, and nothing in that loop checks. `_chain_gap` takes about 0.3s per call on those rings. `_assemble_gap` calls it four times in a row, about 1.2s, with no check between them. A join of two fine outlines spends that time inside `build_surrounds` before the next check.

The pair loops, the bridge-edge loop, and the corner loops do check. These three do not. The named tests never reach them: cancel is already true at the first check, and the two squares are small.

## Remedy

In `src/weedlib/surround.py` only:

- In `_straighten_colinear`, call `progress.check(outline=points)` at the start of each straight side (`for pos, edge in enumerate(sides)`). That is the one ring being smoothed. Do not pass a line.
- In `_gap_overlap`, call `progress.check()` with no outline and no line at the start of each edge of `ring_a` (the `index_a` loop), and the same for each run of `runs_a`. Two rings are in play, so do not name either, and do not name a trial line.
- In `_chain_gap`, call `progress.check()` with no name on each sample point. That covers every call from `_assemble_gap`.

Do not change the points those functions return. Do not catch `WeedCancelled`. Do not edit `progress.py`, the solvers, the figures, or the window.

Add a test the current code fails. A focus hook on a fine outline must see a check per straight side during the straighten, not only the preamble. A cancel that becomes true only after those preamble checks must raise `WeedCancelled` and must not return an outline. A joined pair of fine rings must record a check inside the overlap or chain walk before `build_surrounds` returns. No Inkscape. A smaller ring is enough if the assertion is the check, not the wall time.

## What held

The check before the offset, the check before joins, and the check on each cluster are in place. A group of one path is named as one ring. A group of more than one path is not named. A new bridge edge is one line, `(x0, y0, x1, y1)`, and that same line is passed again while the edge is tested against the subject. An edge that already lies on a ring is not named as a line. Corner and fillet searches name the one ring in `points`.

`progress.check` copies the coordinates and does not call the geometry hook, so the name is not a cut. Nothing in `surround.py` catches `WeedCancelled`, so a cancel does not return the partial `surrounds` list. With no hooks, `check` does not mutate the ring. The existing surround tests still match. `report`, `check_pause`, `check_cancel`, and `report_segment` are unchanged. Solvers, figures, and the window were not edited.

A 12-circle build recorded 11139 focus calls. Each outline was one sequence of `(x, y)` points, and each line was exactly two points.

## Outside this change

`src/weedlib/solvers.py` still calls progress only from `_add_seg`, and only once a segment is accepted. `debug.phase` checks on enter and exit. A pocket or seal search inside one phase can run without a check until it accepts a segment or the phase ends. The runtime says a check only when a segment is accepted does not cover a stretch that can run long. This change did not touch that file. No solver test was re-run.
