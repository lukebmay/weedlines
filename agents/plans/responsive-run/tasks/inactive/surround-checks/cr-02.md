# cr-02

## Result

No defects remain. `pytest tests/test_surround.py tests/test_progress.py` passed (39 passed, 25.46s). Qt loaded. Nothing skipped. The run did not start Inkscape.

Pause and cancel can take effect during the straight-run pair sweep. On the joined 400 by 220 pair, that sweep is about 0.9s and is split across 2016 checks, one per run of the first ring. The longest of those gaps is about 4ms. The longest stretch between any checks on that build, or on one fine ellipse, is about 15ms, inside the straighten walk.

## What held

The change fits the task and the runtime part. `build_surrounds` still checks before the offset, before the joins, and on each cluster. The pair, bridge-edge, and corner loops still check. One ring is named only while that cluster is the work. One new bridge edge is still the one trial line, and that same line is passed again while the edge is tested against the subject. A group that is not one ring is not named.

`_straighten_colinear` still calls `progress.check(outline=points)` once per straight side, before the nested walk. `_chain_gap` still calls `progress.check()` with no name on each sample. `_gap_overlap` calls `progress.check()` with no name once per straight run of the first ring, before that run is compared, then once per edge of that ring. Those checks name neither ring and no line. `WeedCancelled` is not caught. The points those functions return are unchanged. `progress.py` was not extended.

`check` copies the coordinates and does not call the geometry hook, so a name is not a cut. With no hooks, `check` does not mutate the ring, and the existing surround tests still match. A cancel still leaves the caller with no outline.

A check on every pair comparison is not required. On this pair that would be about four million calls. One check per run already lands inside the sweep, and each run is far under a second.

## Outside this change

`src/weedlib/solvers.py` still calls progress only from `_add_seg`, and only when a segment is accepted. `debug.phase` checks on enter and exit. A pocket or seal search inside one phase can run without a check until it accepts a segment or the phase ends. That failure is already the solver-checks task. This change did not touch `solvers.py`. No solver test was re-run.
