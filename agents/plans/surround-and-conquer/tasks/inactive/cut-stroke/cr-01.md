## Summary

The change fits the task. A cut written from the window uses that
window's weed-line color. `run_weedlines_dialog` returns
`(weed, layer_name, color)`. On Apply, `color` is the committed
`weed-line-color` property. A window that does not accept returns
`(None, None, None)`. The control still starts at `#FF0000`.

The host passes that color into `write_result`. The Apply notice
is the same sentence. `write_result` stores `weed_line_color` only
when the argument is not None, and passes it to `write_result_svg`.
`cut_style` is the shared stroke: fill none, width 0.25, round caps
and joins. An omitted color is `#FF0000`. Ids stay `weed-cut-NNNN`.
`_add_weed_layer_from_d` uses that same function.
`_add_weed_layer` passes the color through, and the inline path
passes the color returned with the cuts.

JSON-only import passes a recorded `weed_line_color`, or `#FF0000`
when the payload has none. A result SVG is still copied as written,
so a stroke already in that file is not restyled. The correction
branch returns before the cut color is applied. Preview paint, the
Start gate, and the correction-arrow styles were not retargeted.
`docs/inkscape-extension.md` names the window color, default
`#FF0000`, instead of `#c04000`. `src/weedlib/solvers.py` and
`extensions/inkscape/weedlines.inx` were not edited.

## Note

The color Apply returns is the committed property, not the raw
field text. `_hex_color` keeps `#` and six uppercase hex digits.
An edit that does not commit leaves the previous property, which
is also what the preview paints. The window cannot commit an
empty color. `write_result` omits only None. JSON-only import
treats a missing or other falsy value as `#FF0000`. Those two
checks do not disagree for a color the window writes. That is
not a defect.

Round caps and joins stay in `cut_style`. The task did not name
them. The previous stroke already had them, so the result file
and the inline layer still match.
