## Summary

The change fits the task. The return line and its actions are
ordinary widgets in the dialog layout, directly under the preview
splitter. They are not a message box, a popover, or another
window over the preview.

With a defect, the line is the problem sentence plus the kinds
that are present: dangling ends, figure overlaps, and
self-overlaps. Both actions sit under that line. "Return to
Inkscape" rejects the dialog and writes nothing. "Return to
Inkscape with correction arrows" writes `state['arrows']`, the
batches `refresh_preview` already painted from
`build_arrow_paths`. It then replaces the line with the import
sentence and does not close the window. Width, height, and
viewBox go along as `doc_attrs` when they were given. Start stays
disabled while `blocked` is set. The host file was not edited.
A return does not accept the dialog, so the Apply notice stays
the weed-line notice and does not run for this action.

When the check is clear, the line text is empty, the correction
action is not created, and Start still runs.
