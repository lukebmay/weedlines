## Summary

The change fits the task. `doc_root_attrs` reads the display
unit from `inkscape:document-units` and leaves it unset when
the document names none. `user_unit_scale` is how many inches
one user unit is, from the width or height and the viewBox.
No absolute scale stores one px (1/96 inch). The effect keeps
that dict on the job. The detached host and the inline path
pass both into `run_weedlines_dialog`. The dialog stores them
on `display_unit` and `user_unit_scale`. An unset unit is px
there. The spins are not converted.

## Fit

`agents/architecture/boundary.md` says the job carries
Inkscape's display unit and the scale of one user unit. The
display unit starts as that unit. When the document does not
name one, the window uses px. The library still receives
document user units. This change stores the unit and the
scale. It does not convert the numbers on screen. A named
`px` stays `px` on the job. Only a missing name becomes px,
and only on the dialog.

The same read on an lxml element and on an inkex
`SvgDocumentElement` (no Inkscape process) keeps `mm` with
210mm over a viewBox of 210 as `mm` and 1/25.4. A document
that names none stores no display unit and 1/96. The read
does not use `document_unit`, so it does not create a
namedview or fill in px. Width and viewBox win. inkex
`.scale` is px per user unit, and it is divided by 96 only
when those give no absolute scale. Its failure value of 1
is one px.
